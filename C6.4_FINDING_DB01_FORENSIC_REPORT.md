## 1. Executive Summary

During the Phase C6.3 forensic audit of Oracle ATP Production (`GEADCC8B471D081_SAED2`), two database objects owned by schema `SAED_APP` were discovered with status `INVALID`:
- `PROCEDURE SP_VALIDAR_CONSUMIR_QR`
- `TRIGGER TRG_TUTORES_VALIDA_MENOR`

Both objects had their last DDL timestamp frozen on **2026-08-27**. 

This investigation (**C6.4**) was initiated to establish the exact root cause of invalidation through strictly read-only inspection of Oracle ATP production metadata and empirical reproduction/testing in the local Oracle XE 21c sandbox.

### Key Investigation Outcomes:
1. **Root Cause Identified:** The invalidation was caused entirely by **cascade dependency invalidation** (lazy invalidation). In Oracle Database, executing DDL statements on underlying tables (`PROPIEDADES`, `UNIDADES`, `PERSONAS`) automatically transitions dependent PL/SQL units to status `INVALID`. Because neither object was invoked or manually recompiled after subsequent baseline migrations (`V4.x`, `V5.0`), they remained in this state.
2. **Zero Syntax or Schema Incompatibilities:** Every table, column, data type, and check constraint referenced by both objects is **100% present, intact, and structurally aligned** with the current schema.
3. **Flawless Recompilation in Sandbox:** Executing `ALTER PROCEDURE SP_VALIDAR_CONSUMIR_QR COMPILE` and `ALTER TRIGGER TRG_TUTORES_VALIDA_MENOR COMPILE` in Oracle XE yielded status `VALID` with **0 compilation errors**.
4. **100% Semantic and Security Validation:** Extensive functional testing demonstrated:
   - Valid QR codes are verified, atomically consumed, and recorded in `REGISTROS_ACCESO`.
   - Inexistent, expired, revoked, and exhausted QR codes are rejected with accurate error codes.
   - Cross-property/cross-tenant attempts and anonymous contexts are completely blocked by RLS/VPD (`p_valido = 'N'`).
   - `TRG_TUTORES_VALIDA_MENOR` strictly enforces minority rules (rejecting adult birthdates with `ORA-20040`).
5. **Verdict:** **Classification A — RECOMPILATION ONLY**. No code modifications or schema alterations are required.

## 7. Source Code Analysis

### Stored Procedure: `SP_VALIDAR_CONSUMIR_QR`
```sql
PROCEDURE SP_VALIDAR_CONSUMIR_QR (
    p_token_qr          IN  VARCHAR2,
    p_id_porteria       IN  NUMBER,
    p_portero_usuario   IN  NUMBER,
    p_valido            OUT CHAR,
    p_mensaje           OUT VARCHAR2,
    p_id_visita         OUT NUMBER
) AS
    v_id_qr             QR_ACCESOS.id_qr%TYPE;
    v_fecha_exp         QR_ACCESOS.fecha_expiracion%TYPE;
    v_permitidos        QR_ACCESOS.usos_permitidos%TYPE;
    v_consumidos        QR_ACCESOS.usos_consumidos%TYPE;
    v_estado            QR_ACCESOS.estado%TYPE;
    v_id_unidad         VISITAS.id_unidad%TYPE;
    v_id_visitante      VISITAS.id_visitante%TYPE;
    v_id_persona        VISITANTES.id_persona%TYPE;
    v_id_propiedad      PROPIEDADES.id_propiedad%TYPE;
BEGIN
    p_valido := 'N';

    -- Pessimistic row locking to prevent concurrent gate bypass
    SELECT q.id_qr, q.id_visita, q.fecha_expiracion, q.usos_permitidos, q.usos_consumidos, q.estado,
           v.id_unidad, v.id_visitante, vis.id_persona, p.id_propiedad
    INTO v_id_qr, p_id_visita, v_fecha_exp, v_permitidos, v_consumidos, v_estado,
         v_id_unidad, v_id_visitante, v_id_persona, v_id_propiedad
    FROM QR_ACCESOS q
    JOIN VISITAS v ON v.id_visita = q.id_visita
    JOIN VISITANTES vis ON vis.id_visitante = v.id_visitante
    JOIN UNIDADES u ON u.id_unidad = v.id_unidad
    JOIN PROPIEDADES p ON p.id_propiedad = u.id_propiedad
    WHERE q.token_qr = p_token_qr
    FOR UPDATE OF q.usos_consumidos;

    IF v_estado != 'ACTIVO' THEN
        p_mensaje := 'El código QR no se encuentra activo (Estado: ' || v_estado || ').';
        RETURN;
    END IF;

    IF v_fecha_exp < FROM_TZ(CAST(SYSTIMESTAMP AS TIMESTAMP), 'America/Bogota') THEN
        UPDATE QR_ACCESOS SET estado = 'EXPIRADO' WHERE id_qr = v_id_qr;
        p_mensaje := 'El código QR ha expirado.';
        RETURN;
    END IF;

    -- Atomic consumption
    v_consumidos := v_consumidos + 1;
    UPDATE QR_ACCESOS
    SET usos_consumidos = v_consumidos,
        estado = CASE WHEN v_consumidos >= v_permitidos THEN 'USADO' ELSE 'ACTIVO' END
    WHERE id_qr = v_id_qr;

    -- Audit log of access
    INSERT INTO REGISTROS_ACCESO (
        id_propiedad, id_porteria, id_visita, id_persona, id_unidad, id_qr,
        tipo_movimiento, metodo_autorizacion, portero_operador
    ) VALUES (
        v_id_propiedad, p_id_porteria, p_id_visita, v_id_persona, v_id_unidad, v_id_qr,
        'ENTRADA', 'QR_SCAN', p_portero_usuario
    );

    p_valido := 'S';
    p_mensaje := 'Acceso autorizado exitosamente.';
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        p_mensaje := 'Código QR no encontrado o inválido.';
    WHEN OTHERS THEN
        p_mensaje := 'Error interno al validar QR: ' || SQLERRM;
END SP_VALIDAR_CONSUMIR_QR;
```

### Trigger: `TRG_TUTORES_VALIDA_MENOR`
```sql
TRIGGER TRG_TUTORES_VALIDA_MENOR
    BEFORE INSERT OR UPDATE ON TUTORES
    FOR EACH ROW
DECLARE
    v_fecha_nac DATE;
BEGIN
    SELECT fecha_nacimiento INTO v_fecha_nac FROM PERSONAS WHERE id_persona = :NEW.id_persona_menor;
    IF v_fecha_nac IS NULL OR MONTHS_BETWEEN(TRUNC(SYSDATE), v_fecha_nac) / 12 >= 18 THEN
        RAISE_APPLICATION_ERROR(-20040, 'id_persona_menor debe corresponder a una persona menor de edad.');
    END IF;
END;
```

1. All anchored types (`QR_ACCESOS.id_qr%TYPE`, etc.) match actual table definitions.
2. The pessimistic lock `FOR UPDATE OF q.usos_consumidos` exclusively locks the single QR row being processed.
3. Values for `tipo_movimiento` (`'ENTRADA'`) and `metodo_autorizacion` (`'QR_SCAN'`) comply with check constraints `CK_REGACCESO_TIPO` and `CK_REGACCESO_METODO`.
4. Values for `estado` (`'ACTIVO'`, `'USADO'`, `'EXPIRADO'`) comply with `CK_QR_ESTADO`.
5. Error handling wraps unexpected exceptions without leaking unhandled database deadlocks.

## 8. Exact Root Cause

### Classification: `DEPENDENCY_INVALIDATION` (Cascade Lazy Invalidation)

**Chronological Forensic Reconstruction:**
1. **2026-08-27 20:40:02:** `SP_VALIDAR_CONSUMIR_QR` was created in Oracle ATP during initial baseline import (`V3.9`). Status: `VALID`.
2. **2026-08-27 20:40:38:** `TRG_TUTORES_VALIDA_MENOR` was created on `TUTORES`. Status: `VALID`.
3. **2026-08-27 20:49:42:** Subsequent schema migrations executed `ALTER TABLE` statements on `UNIDADES` and `PERSONAS`.
4. **2026-08-28 00:47:31:** Further migrations altered `PROPIEDADES` (including adding constraints and RLS security policies).
5. **Oracle Kernel Action:** By design, the Oracle database invalidates all compiled units that maintain a `HARD` dependency on modified tables. Because `SP_VALIDAR_CONSUMIR_QR` depends on `PROPIEDADES` and `UNIDADES`, and `TRG_TUTORES_VALIDA_MENOR` depends on `PERSONAS`, Oracle flipped their status in `OBJ$` to `INVALID`.
6. **Absence of Invocation:** In SAED 2.0, the backend currently exposes QR and Tutor services primarily via Spring JDBC repositories rather than direct calls to this specific legacy stored procedure. Consequently, Oracle never triggered an automatic on-demand recompilation.
