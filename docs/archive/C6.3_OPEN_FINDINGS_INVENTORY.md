## 1. Executive Summary

Following the successful production certification of **C6.2.2** (where `FK_AUDITORIA_PROPIEDAD` was dropped on Oracle ATP in 55 ms, permanently resolving the `ORA-00060` deadlock), SAED 2.0 entered the **C6.3 Checkpoint**.

The core system architecture has reached unprecedented stability:
- **Oracle ATP Production** (`GEADCC8B471D081_SAED2`) is operational with **100% data integrity**, **active RLS/VPD** (90 policies enabled), and **session-local context** (`SAED_CTX ACCESSED LOCALLY`).
- **Autonomous audit logging** operates smoothly without self-deadlocks.
- All 12 adversarial attack suites (**A–L**) remain green (`12/12 PASS`).
- Frozen certified components (**SUPERADMIN V1 RC1**, **C4 Wompi Payment Gateway**, **C6.1.2 Session Context**, and **C6.2.2 Audit Decoupling**) are strictly preserved and untouched.

The primary objective of Phase C6.3 is **exhaustive discovery, classification, and risk prioritization** across 37 technical and architectural inspection vectors to identify the single most critical risk to address in the next stabilization cycle (**C6.4**).

## 5. Superseded Findings

The following proposed solutions and historical approaches are formally superseded:

1. **Mandatory SGA Global Flush (`ALTER SYSTEM FLUSH GLOBAL_CONTEXT`):**  
   *Reason:* Proven unnecessary in C6.1.2-PRE. In Oracle ATP, executing `CREATE OR REPLACE CONTEXT SAED_CTX USING ... ACCESSED LOCALLY` instantaneously redefines the namespace and clears global memory structures without requiring instance-level SGA flushes.
2. **Application-Layer DataSource Proxy Workarounds for Session Bleed:**  
   *Reason:* Pre-checkout and post-checkin ThreadLocal cleanup was insufficient when multiple physical queries shared a connection without continuous context re-injection. The root engine fix (`SAED_CTX ACCESSED LOCALLY`) natively solved this at the kernel level.
3. **Removal of Autonomous Transactions from `SP_REGISTRAR_AUDITORIA` (Solution B):**  
   *Reason:* Solution B would couple audit entries to parent business transactions, causing audit logs to vanish on transaction rollbacks (destroying non-repudiation). Solution A (`DROP CONSTRAINT FK_AUDITORIA_PROPIEDAD`) fully resolved the deadlock while preserving audit autonomy.

## 6. False Positives

1. **`WompiPaymentFlowAdversarialTest` Post-Webhook Zero-Row Query Assertion:**  
   *Evidence:* In `WompiServiceImpl.procesarWebhook()`, the method correctly invokes `PKG_SAED_SESSION.CLEAR_CONTEXT()` upon completion to guarantee thread hygiene. This is **expected, secure RLS behavior**, not an application failure.

   *Evidence:* Generic CVE analyzers flag the Oracle JDBC thin driver against full Oracle Database Enterprise Server CVEs. Properly documented and suppressed via `owasp-suppressions.xml`.

## 9. Production Findings (Oracle ATP & Cloud Infrastructure)

The live, strictly read-only inspection of Oracle ATP (`GEADCC8B471D081_SAED2`) identified two specific production artifacts:

### PROD-01: Invalid Production Database Objects (`SP_VALIDAR_CONSUMIR_QR`, `TRG_TUTORES_VALIDA_MENOR`)
- **Location:** Oracle ATP Schema `SAED_APP`.
- **Observed State:**  
  - `PROCEDURE SP_VALIDAR_CONSUMIR_QR` -> `STATUS = 'INVALID'`, Created: `2026-08-27 20:40:02`.
  - `TRIGGER TRG_TUTORES_VALIDA_MENOR` -> `STATUS = 'INVALID'`, Created: `2026-08-27 20:40:38`.
- **Root Cause:** Subsequent schema modifications (such as RLS policy definitions, column alterations, or constraint drops) automatically invalidated dependent PL/SQL objects in the Oracle data dictionary. Oracle has not attempted recompilation because the specific procedures/triggers have not been invoked since the baseline migrations.
- **Risk:** If an authorized porter or user invokes the QR consumption procedure or modifies a minor tutor, runtime execution may fail or trigger an unexpected recompilation error under RLS restrictions.

### PROD-02: Cloud Deployment HealthCheck Misalignment
- **Location:** `render.yaml`.
- **Observed State:** HealthCheck configured as `healthCheckPath: /api/v1/auth/login` with HTTP method expectations.
- **Risk:** Potential container restart churn during cold boots if the auth endpoint responds with 405 Method Not Allowed to HTTP GET probes.

## 12. Proposed C6.4 Investigation Plan

### Phase Identifier: `C6.4 — Forensic Investigation & Sandbox Validation of Invalid Production DB Objects`

* **Objective:** Determine the exact cause of invalidation for `SP_VALIDAR_CONSUMIR_QR` and `TRG_TUTORES_VALIDA_MENOR`, verify whether compilation errors exist, test recompilation and end-to-end execution in Oracle XE local sandbox, and prepare a safe runbook for production.
* **Hypothesis:** Subsequent RLS policies applied to `PROPIEDADES`, `VISITAS`, `QR_ACCESOS`, and `PERSONAS` caused Oracle to flag dependent PL/SQL units as `INVALID`. The objects either compile cleanly upon explicit recompilation or require minor alignment with modern schema types.
* **Necessary Evidence:**
  1. Full source code and dependency tree of both objects from the Oracle ATP data dictionary.
  2. Test compilation results in Oracle XE sandbox (`ALTER PROCEDURE ... COMPILE`, `ALTER TRIGGER ... COMPILE`).
  3. Empirical invocation of `SP_VALIDAR_CONSUMIR_QR` with pessimistic locking under session-local context.
  4. Empirical test of `TRG_TUTORES_VALIDA_MENOR` verifying rejection of adult birthdates.
* **Required Sandbox:** Local Oracle XE 21c container (`saed-oracle-xe` / `SAED_BASELINE_TEST_01`).
* **Required Tests:**
  1. `QrValidationAdversarialTest`: Valid token, expired token, exhausted token, concurrent multi-gate swipe.
  2. `TutorValidationIntegrationTest`: Minor insertion (success), adult insertion (ORA-20040 expected), null birthdate handling.
* **PASS Criteria:**
  - Both objects compile with **zero errors** in Oracle XE.
  - Zero regression on existing 12 adversarial test suites.
  - Verification that RLS policies do not trigger recursive loop errors during `SP_VALIDAR_CONSUMIR_QR` execution.
* **FAIL Criteria:**
  - ORA-00904 (invalid identifier), ORA-00942 (table does not exist), or PL/SQL compilation errors during compilation in sandbox.
  - Lock contention or deadlock during pessimistic row lock `FOR UPDATE OF q.usos_consumidos`.
* **Strict Constraints:**
  - Oracle ATP remains **100% READ-ONLY** during C6.4 investigation.
  - **Zero DDL, Zero DML, Zero DCL** on production.
  - All experiments conducted exclusively in Oracle XE local.
* **Subsequent Production Change Required:**
  - Yes: Once validated in XE, a controlled execution runbook (`C6.4.1`) will be submitted for user authorization to recompile the objects in Oracle ATP.
