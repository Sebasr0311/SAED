# F10-04 — Votaciones y Toma de Decisiones en Asambleas (Ley 675)
**SAED 2.0 — Property Management & Governance Platform**  
*Phase 10: Documentation, Regulations & Property Governance — Module 04*

## 1. Executive Summary

Module **F10-04 Votaciones** provides comprehensive, enterprise-grade statutory voting, ballot tallying, and decision-making management for horizontal property co-ownership assemblies in full compliance with **Colombian Law 675 of 2001 (Régimen de Propiedad Horizontal)**, specifically Articles 37, 39, 45, and 46.

Building upon the assembly governance foundation established in F10-03, F10-04 formalizes deliberative decision-making into an auditable, cryptographically validated, and tamper-resistant voting workflow with:
- **Statutory Quorum & Majority Types:** Full support for `SIMPLE_50_MAS_1` (ordinary matters under Art. 45) and `CALIFICADA_70` (special qualified decisions requiring at least 70% of total property coefficients under Art. 46, such as changes affecting common goods, reconstruction, or extraordinary financial obligations).
- **Coefficient-Weighted Balloting:** Every ballot option (`SI`, `NO`, `BLANCO`, `ABSTENCION`) is weighted strictly by the unit's co-ownership coefficient (`COEFICIENTE_COPROPIEDAD`), ensuring mathematical precision to four decimal places.
- **Strict Single-Vote Constraint:** Uniqueness enforced at both relational database level (`UQ_VOTOS_VOTACION_UNIDAD`) and transactional application tier, strictly preventing duplicate ballots from the same unit.
- **Auditable Proxy Voting Workflow:** Automatic verification against approved powers of attorney (`PODERES_REPRESENTACION.ESTADO = 'APROBADO'`). Rejection of unapproved, pending, or rejected proxies with HTTP 403 Forbidden. Automatic resolution of voter persona ID to eliminate identity spoofing.
- **Voter Eligibility & Cross-Property Protection:** Verification of unit coproperty ownership and occupancy (`PROPIETARIOS_UNIDAD`, `RESIDENTES_UNIDAD`, `USUARIO_ASIGNACIONES`). Cross-property voting attempts are strictly blocked with HTTP 400 or 403.
- **Pessimistic Concurrency Control:** `SELECT ... FOR UPDATE` row locks on `VOTACIONES` preventing race conditions during concurrent ballot submissions, closures, and annulments.
- **Point Annulment Lifecycle (`ANULADA`):** Authorized administrators can annul an active or corrupted voting item (`PUT /api/v1/asambleas/{id}/votaciones/{idVotacion}/anular`), preserving full immutable history in `AUDITORIA_LOG`.
- **Resident Interactive Ballot UI:** Real-time web ballot for residents and verified proxies on `ResAsambleasPage.jsx` with instant coefficient confirmation and visual feedback.

## 2. Statutory Legal Framework (Ley 675 de 2001)

| Article | Statutory Mandate | SAED 2.0 Implementation |
| :--- | :--- | :--- |
| **Art. 37** | The Assembly is composed of all private unit owners or their legal proxies. | `usuarioPerteneceAUnidad()` and `esApoderadoAprobado()` enforce eligibility. Self-delegation is rejected. |
| **Art. 39** | Assemblies can only deliberate and decide with statutory quorum. | Assembly status must be `CONVOCADA` or `EN_CURSO`. Real-time quorum check against total co-ownership coefficients. |
| **Art. 45** | Ordinary decisions require a simple majority of voting coefficients present (`50% + 1`). | Type `SIMPLE_50_MAS_1`: Approved if `VOTOS_SI > (VOTOS_SI + VOTOS_NO + VOTOS_BLANCO) / 2`. |
| **Art. 46** | Qualified majority decisions require at least 70% of total property coefficients. | Type `CALIFICADA_70`: Approved only if `VOTOS_SI >= 0.70` (or 70.00% of total property coefficient). |

## 3. Relational Schema & Constraints

### 3.1 Core Database Tables

```sql
-- Agenda Voting Items
CREATE TABLE VOTACIONES (
    ID_VOTACION NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ID_ASAMBLEA NUMBER NOT NULL,
    PUNTO_ORDEN_DIA NUMBER NOT NULL,
    TITULO VARCHAR2(255 CHAR) NOT NULL,
    DESCRIPCION VARCHAR2(1000 CHAR),
    TIPO_MAYORIA_REQUERIDA VARCHAR2(30 CHAR) NOT NULL,
    HORA_APERTURA TIMESTAMP WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
    HORA_CIERRE TIMESTAMP WITH TIME ZONE,
    ESTADO VARCHAR2(20 CHAR) DEFAULT 'ABIERTA' NOT NULL,
    VOTOS_SI NUMBER(8,4) DEFAULT 0 NOT NULL,
    VOTOS_NO NUMBER(8,4) DEFAULT 0 NOT NULL,
    VOTOS_BLANCO NUMBER(8,4) DEFAULT 0 NOT NULL,
    VOTOS_ABSTENCION NUMBER(8,4) DEFAULT 0 NOT NULL,
    TOTAL_VOTOS NUMBER(8,4) DEFAULT 0 NOT NULL,
    APROBADA NUMBER(1) DEFAULT 0 NOT NULL,
    FECHA_CREACION TIMESTAMP WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT FK_VOTACIONES_ASAMBLEA FOREIGN KEY (ID_ASAMBLEA) REFERENCES ASAMBLEAS (ID_ASAMBLEA) ON DELETE CASCADE,
    CONSTRAINT CK_VOTACIONES_MAYORIA CHECK (TIPO_MAYORIA_REQUERIDA IN ('SIMPLE_50_MAS_1', 'CALIFICADA_70')),
    CONSTRAINT CK_VOTACIONES_ESTADO CHECK (ESTADO IN ('ABIERTA', 'CERRADA', 'ANULADA'))
);

-- Individual Ballots Cast
CREATE TABLE VOTOS (
    ID_VOTO NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    ID_VOTACION NUMBER NOT NULL,
    ID_UNIDAD NUMBER NOT NULL,
    ID_PERSONA_VOTANTE NUMBER NOT NULL,
    OPCION_VOTO VARCHAR2(20 CHAR) NOT NULL,
    COEFICIENTE_VOTO NUMBER(8,4) NOT NULL,
    FECHA_HORA TIMESTAMP WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT FK_VOTOS_VOTACION FOREIGN KEY (ID_VOTACION) REFERENCES VOTACIONES (ID_VOTACION) ON DELETE CASCADE,
    CONSTRAINT FK_VOTOS_UNIDAD FOREIGN KEY (ID_UNIDAD) REFERENCES UNIDADES (ID_UNIDAD),
    CONSTRAINT FK_VOTOS_PERSONA FOREIGN KEY (ID_PERSONA_VOTANTE) REFERENCES PERSONAS (ID_PERSONA),
    CONSTRAINT CK_VOTOS_OPCION CHECK (OPCION_VOTO IN ('SI', 'NO', 'BLANCO', 'ABSTENCION')),
    CONSTRAINT UQ_VOTOS_VOTACION_UNIDAD UNIQUE (ID_VOTACION, ID_UNIDAD)
);
```

### 3.2 Integrity and Isolation Indexes

```sql
CREATE INDEX IX_VOTACIONES_ASAMBLEA ON VOTACIONES (ID_ASAMBLEA, ESTADO);
CREATE INDEX IX_VOTOS_VOTACION ON VOTOS (ID_VOTACION, ID_UNIDAD);
CREATE INDEX IX_VOTOS_UNIDAD ON VOTOS (ID_UNIDAD);
```

## 4. Security, Multitenancy & Oracle RLS

### 4.1 Oracle Virtual Private Database (RLS) & Bootstrap Context
- When a resident acts as an authorized proxy for another unit within the same co-ownership, Oracle VPD (`FN_FILTRO_UNIDAD`) restricts direct queries on `UNIDADES` to the user's personal assignment.
- `AsambleaRepositoryImpl` implements an elevated bootstrap context pattern (`PKG_SAED_SESSION.SET_BOOTSTRAP_CONTEXT(1)`) strictly scoped within `findPropiedadUnidad()` and `findCoeficienteUnidad()`, immediately restoring the caller's session context in a `finally` block to guarantee Zero-Trust tenant safety without context bleeding.

### 4.2 Module Entitlement (Commercial Plans)
- Gated via `ModuleEntitlementService.checkEntitlement("ASAMBLEAS")`.
- `FREE` & `PRO` plans: Blocked with HTTP 403 (`ModuleNotEntitledException`).
- `ENTERPRISE` plan: Permitted with full voting capabilities.

### 4.3 Role Permissions & Endpoint Security

| Endpoint | Method | Allowed Roles | Description |
| :--- | :---: | :--- | :--- |
| `/api/v1/asambleas/{id}/votaciones` | `GET` | All authenticated assembly participants | Lists voting points and live tallies |
| `/api/v1/asambleas/{id}/votaciones` | `POST` | `SUPERADMIN`, `ADMIN_ORGANIZACION`, `ADMIN_PROPIEDAD` | Creates a new voting point (`ABIERTA`) |
| `/api/v1/asambleas/{id}/votaciones/{v}/cerrar` | `PUT` | `SUPERADMIN`, `ADMIN_ORGANIZACION`, `ADMIN_PROPIEDAD` | Closes voting and calculates result |
| `/api/v1/asambleas/{id}/votaciones/{v}/anular` | `PUT` | `SUPERADMIN`, `ADMIN_ORGANIZACION`, `ADMIN_PROPIEDAD` | Annuls voting point with audit log |
| `/api/v1/asambleas/{id}/votaciones/{v}/votar` | `POST` | `SUPERADMIN`, `ADMIN_ORG`, `ADMIN_PROP`, `RESIDENTE`, `PROPIETARIO` | Emits coefficient-weighted ballot |

## 5. End-to-End Voting Workflow & Business Rules

```
┌─────────────────┐       ┌─────────────────┐       ┌──────────────────┐
│  Admin creates  │       │ Resident/Proxy  │       │  Admin closes    │
│  Voting Point   │──────>│  Casts Ballot   │──────>│  Voting Point    │
│ (Pessimistic Lk)│       │(Pessimistic Lk) │       │ (Auto-Tally Ley) │
└─────────────────┘       └─────────────────┘       └──────────────────┘
         │                         │                          │
         ▼                         ▼                          ▼
   AUDITORIA_LOG             AUDITORIA_LOG              AUDITORIA_LOG
  (CREAR_PUNTO)              (EMITIR_VOTO)             (CERRAR_VOTACION)
```

1. **Voter Persona Auto-Resolution:** The backend automatically identifies the authenticated user's persona ID from the security context, ignoring spoofed values in the JSON request payload.
2. **Proxy Legal Check:** If voting for a unit other than their own assignment, the system queries `PODERES_REPRESENTACION` for `ID_ASAMBLEA`, `ID_UNIDAD`, and `ID_PERSONA_APODERADO`. If `ESTADO != 'APROBADO'`, voting is immediately rejected with HTTP 403 Forbidden.
3. **Pessimistic Lock & Idempotency:** The voting record is locked via `FOR UPDATE` before ballot insertion to eliminate concurrency race conditions. Duplicate votes are rejected with HTTP 400 (`UQ_VOTOS_VOTACION_UNIDAD`).
4. **Weighted Tallies:** Ballots add coefficient fractions directly to `VOTOS_SI`, `VOTOS_NO`, `VOTOS_BLANCO`, and `VOTOS_ABSTENCION`.
5. **Approval Computation on Close:**
   - **`SIMPLE_50_MAS_1`:** `APROBADA = (votosSi > (votosSi + votosNo + votosBlanco) / 2)`.
   - **`CALIFICADA_70`:** `APROBADA = (votosSi >= 0.70)` (over total property coefficient).
