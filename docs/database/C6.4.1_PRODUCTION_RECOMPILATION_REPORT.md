### 28. Residual Risks

1. **Lazy Cascade Invalidation on Future Schema Evolution:** If future migration scripts alter columns or table definitions in `PROPIEDADES`, `UNIDADES`, `PERSONAS`, or `TUTORES`, Oracle will again mark dependent procedures and triggers as `INVALID` until recompiled. Future migration pipelines should include post-migration compilation sweeps (`DBMS_UTILITY.COMPILE_SCHEMA`).
2. **Operational Impact:** None. Both objects are now `VALID` and available for execution without on-demand recompilation latency.

---

### 29. Rollback Strategy

Because the recompilation operation (`ALTER ... COMPILE`) only updates the dictionary dependency status and compiles internal bytecode without modifying source code, rollback to an "invalid" state is neither semantically meaningful nor technically required. Had recompilation failed, the safe protocol prescribed stopping without applying blind repairs, preserving pre-change source hashes and logs, and diagnosing root cause in XE.
