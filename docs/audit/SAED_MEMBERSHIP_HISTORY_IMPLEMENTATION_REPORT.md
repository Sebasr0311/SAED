### 3. Esquema Físico Verificado (Oracle ATP / XE)

La tabla canónica `MEMBRESIAS_HISTORIAL` en `SAED_SEC_MASTER`:

```sql
CREATE TABLE "MEMBRESIAS_HISTORIAL" (
    "ID_HISTORIAL"     NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
    "ID_MEMBRESIA"     NUMBER NOT NULL,
    "ID_PLAN_ANTERIOR" NUMBER,
    "ID_PLAN_NUEVO"    NUMBER NOT NULL,
    "TIPO_CAMBIO"      VARCHAR2(20 CHAR) NOT NULL,
    "OBSERVACIONES"    VARCHAR2(500 CHAR),
    "FECHA_CAMBIO"     TIMESTAMP (6) WITH TIME ZONE DEFAULT FROM_TZ(CAST(SYSTIMESTAMP AS TIMESTAMP), 'America/Bogota') NOT NULL,
    "REALIZADO_POR"    NUMBER
);
```

#### Restricciones y Claves Foráneas:
- `CK_MEMBHIST_TIPO`: `tipo_cambio IN ('INICIO', 'UPGRADE', 'DOWNGRADE', 'RENOVACION', 'CANCELACION', 'SUSPENSION', 'REACTIVACION')`
- `FK_MEMBHIST_MEMBRESIA`: `FOREIGN KEY (ID_MEMBRESIA) REFERENCES MEMBRESIAS(ID_MEMBRESIA)`
- `FK_MEMBHIST_PLANANT`: `FOREIGN KEY (ID_PLAN_ANTERIOR) REFERENCES PLANES(ID_PLAN)`
- `FK_MEMBHIST_PLANNUEVO`: `FOREIGN KEY (ID_PLAN_NUEVO) REFERENCES PLANES(ID_PLAN)`
- `FK_MEMBHIST_USUARIO`: `FOREIGN KEY (REALIZADO_POR) REFERENCES USUARIOS(ID_USUARIO)`

### 4. Trigger de Inmutabilidad y Pruebas de Intento UPDATE / DELETE

Trigger de base de datos verificado en `V5.0__master_baseline.sql` (líneas 4124-4128):

```sql
CREATE OR REPLACE TRIGGER "TRG_MEMBHIST_IMMUTABLE"
    BEFORE UPDATE OR DELETE ON MEMBRESIAS_HISTORIAL
    FOR EACH ROW
BEGIN
    RAISE_APPLICATION_ERROR(-20030, 'MEMBRESIAS_HISTORIAL es append-only.');
END;
```

#### Certificación de Inmutabilidad en Pruebas Automatizadas:
- **Test 10 (`test10_trigger_inmutabilidad_bloqueaUpdate`)**: Ejecuta un `UPDATE` directo vía JDBC. La base de datos arroja `ORA-20030: MEMBRESIAS_HISTORIAL es append-only.` y revierte la transacción.
- **Test 11 (`test11_trigger_inmutabilidad_bloqueaDelete`)**: Ejecuta un `DELETE` directo vía JDBC. La base de datos arroja `ORA-20030: MEMBRESIAS_HISTORIAL es append-only.` y protege la bitácora contra borrado accidental o malicioso.

### 6. Manejo de Claves Foráneas y Protección ORA-02291

La columna `REALIZADO_POR` posee restricción de clave foránea `FK_MEMBHIST_USUARIO` hacia `USUARIOS(ID_USUARIO)`.
- Si la acción proviene de un actor anónimo, webhook asíncrono o ID sintético que no existe en `USUARIOS`, el servicio normaliza de forma segura el valor a `NULL`:
```java
if (realizadoPor != null && realizadoPor > 0) {
    Integer countUsr = jdbcTemplate.queryForObject(
            "SELECT COUNT(*) FROM USUARIOS WHERE ID_USUARIO = :usr",
            new MapSqlParameterSource("usr", realizadoPor), Integer.class);
    if (countUsr != null && countUsr > 0) {
        validRealizadoPor = realizadoPor;
    } else {
        log.warn("[MembershipHistory] Usuario realizadoPor={} no existe en USUARIOS. Se registra como NULL.", realizadoPor);
    }
}
```
- Mismo tratamiento defensivo se aplica a `ID_PLAN_ANTERIOR` para garantizar integridad referencial estricta y zero ORA-02291.
- **Test 13 (`test13_service_protegeClaveForaneaUsuarioInexistente`)**: Certifica que un ID `999999999` se normaliza a `NULL` sin error.

### 7. Endpoints de Consulta Implementados

1. **Plataforma (SUPERADMIN)**:
   - `GET /api/v1/platform/memberships/{id}/historial`
   - Requiere: `hasAuthority('SCOPE_SUPERADMIN')`
   - Retorna: DTO enriquecido con nombres y códigos de planes anterior y nuevo, observaciones, fecha formateada y usuario responsable.

2. **Organización / Finanzas (Tenant Isolation)**:
   - `GET /api/v1/membresias/{id}/historial`
   - Requiere: `hasAnyAuthority('SCOPE_SUPERADMIN', 'SCOPE_ADMIN_ORGANIZACION')`
   - Aislamiento Zero-Trust: Si el solicitante es `ADMIN_ORGANIZACION`, el backend valida en Oracle que `m.ID_ORGANIZACION == ctx.getOrganizationId()`. Si intenta consultar el historial de otra organización, se deniega inmediatamente (`403` / `ApiResponse.error`).
