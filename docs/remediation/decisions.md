# Remediation product decisions (defaults)

Date: 2026-10-09. The product owner delegated these decisions ("fix everything, continue without asking"). Each default is conservative, follows the master document where it is explicit, and can be revisited. Every implementation that depends on one of them cites its ID.

| ID | Decision | Rationale |
|---|---|---|
| DEC-01 PERSONAS RLS | PERSONAS keeps no row-level policy. Isolation is enforced in application SQL and is verified by the cross-tenant matrix (persons of another organization are never returned; direct ids give 404). | PERSONAS is a global identity table (visitors and workers are shared across tenants; document numbers are globally unique). Startup and V5.28 deliberately drop its policy to avoid VPD recursion. A policy would need a redesign of visitor identity first. |
| DEC-02 SUPERADMIN visibility | SUPERADMIN manages platform data (organizations, properties as tenant containers, plans, memberships, organization administrators). It must not read operational data (residents, persons, payments, fees, packages, visits, PQRS, assemblies) except through explicit audited support endpoints. | Master document: "the Superadmin does not see operational data"; audit F3-02. |
| DEC-03 Voting (D03) | A vote is accepted only when the assembly is `EN_CURSO` and the voting is `ABIERTA`; `CONVOCADA` is rejected. Only the unit's legal owner (PROPIETARIOS_UNIDAD active) or an approved proxy (PODERES_REPRESENTACION `APROBADO`) may vote, once per unit. The unit must have registered attendance in the assembly. Weight is the unit's registered coefficient; a missing coefficient rejects the vote. | Ley 675 de 2001 (owners vote by coefficient; proxies allowed); master document F10. |
| DEC-04 Coefficients (D04) | Coefficients are fractions (0 < c ≤ 1). Saving a unit coefficient that makes the property sum exceed 1.0000 (4-decimal tolerance) is rejected; an incomplete sum is allowed and reported as a warning in the property summary. | Prevents impossible states without blocking incremental census entry. |
| DEC-05 PQRS SLA (D05) | Default SLA by priority: CRITICA 1 h, ALTA 4 h, MEDIA 24 h, BAJA 72 h, wall-clock hours. A ticket is "at risk" at 75 % of its SLA and "overdue" past 100 %. | Master document values; business-hour calendars deferred. |
| DEC-06 Onboarding (D06) | Paid plans are provisioned only after verified payment (Wompi event or admin approval). A trial is allowed only for a plan flagged as trial-eligible, once per tax id/e-mail. Client-supplied `esPrueba` is ignored. | Audit F3-04/F3-08. |
| DEC-07 Deletion (D07) | Properties with financial/legal/audit history cannot be hard-deleted; they are deactivated. (Implemented.) | Master document retention; implemented in C-07. |
| DEC-08 Rates (D09) | Monthly fee = property budget share by unit coefficient, unless a fixed fee is configured. Early-payment discount and late-payment interest are per-property settings that default to 0 % (disabled). Interest, when enabled, is simple monthly interest capped by the configured rate. | No legal rate is invented; behavior is complete and configurable. |
| DEC-09 Default contract template | No template is seeded at application startup. A default template is created for a new organization during organization provisioning. | Startup must not write tenant data (F01-01). |
| DEC-10 Package PIN | Every active resident of the recipient unit may see the PIN (same audience as notifications). | Implemented in C-11; matches current notification audience. |
| DEC-11 Voting result on close (F10-12) | Closing a voting computes the result per option weighted by the unit coefficient (one vote per unit) and stores it with the closing: winning option (`EMPATE` on a tie, none without votes), weight per option, total weight cast, the property coefficient base (sum of active-unit coefficients at close), the represented coefficients (attendance still registered at close, proxies included), SI percentage of the legal denominator and `APROBADA`/`RECHAZADA`. Majorities follow Ley 675: `SIMPLE_50_MAS_1` = SI weight > 50 % of the coefficients represented in the session (art. 45); `CALIFICADA_70_PCT` = SI weight >= 70 % of the total coefficients of the property (art. 46); `UNANIMIDAD_100_PCT` = SI weight equals the represented coefficients (every represented coefficient voted SI; assumption, the law defines no separate rule). Represented units that did not vote therefore count against the majority. A voting without votes is `RECHAZADA`. Closing is done once under a row lock; a closed voting is neither re-closed nor annulled. | Ley 675 de 2001 arts. 45 and 46 (replaces an earlier draft that used the weight cast as denominator). |
| DEC-12 Resident relation on registration | Registering a user with role `RESIDENTE` stores a real `RESIDENTES_UNIDAD.TIPO_RESIDENTE` taken from the optional request field `tipoResidente` (`PROPIETARIO` or `ARRENDATARIO`, case-insensitive); any other value is rejected with 400. When the field is absent the relation defaults to `PROPIETARIO`. `TITULAR` is not a stored value: the constraint `CK_RESIDUNIDAD_TIPO` (V5.0, extended with `CONVIVIENTE` by V5.9) is the single source of truth and startup DDL no longer widens it. | The API carried no relation; the owner is the conservative default and matches the isolated fixtures. |
