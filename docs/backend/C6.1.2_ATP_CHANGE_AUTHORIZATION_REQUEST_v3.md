## 1. Executive Summary

Este documento constituye el **Plan Definitivo de Ejecución y Runbook de Producción (v3)** para migrar el contexto de seguridad de la base de datos `SAED_CTX` desde `ACCESSED GLOBALLY` hacia `ACCESSED LOCALLY` (SESSION-LOCAL) en **Oracle ATP**.

El cambio elimina de raíz la vulnerabilidad de fuga de contexto entre tenants (Context Bleed), suprime las colisiones de concurrencia en la autenticación bootstrap (`ORA-20086`), y garantiza que las transacciones multi-query en vuelo queden totalmente blindadas contra sobreescrituras en memoria compartida.

**Estado Actual:** Oracle ATP permanece **100% INTACTO y READ-ONLY**. No se ha ejecutado ningún DDL, DCL ni DML en producción.

## 2. Diagnóstico y Causa Raíz

En la migración canónica `database/migrations/V5.0__master_baseline.sql` (línea 35), el contexto se definió como:
```sql
CREATE OR REPLACE CONTEXT SAED_CTX USING SAED_APP.PKG_SAED_SESSION ACCESSED GLOBALLY;
```

### Impacto Técnico de `ACCESSED GLOBALLY`:
1. **Memoria en SGA (Shared Pool):** Al no suministrarse un `client_id` (`DBMS_SESSION.SET_IDENTIFIER`), Oracle asigna los atributos del contexto en la memoria compartida del sistema (SGA), haciéndolos visibles y modificables por cualquier sesión física.
2. **Context Bleed entre Conexiones:** Una conexión física B hereda pasivamente los atributos establecidos por una conexión física A.
3. **Colisiones de Identidad Bootstrap (`ORA-20086`):** En alta concurrencia, llamadas simultáneas a `SET_BOOTSTRAP_CONTEXT` sobreescriben la variable global de usuario en la SGA antes de que el hilo complete `SET_CONTEXT`.
4. **Sobreescritura en Transacciones Multi-Query:** Dentro de un `@Transactional` de Spring, la Conexión 1 ejecuta una consulta para el Tenant 1. Si en paralelo la Conexión 2 establece el contexto para el Tenant 2, la Conexión 1 lee los datos del Tenant 2 en sus consultas subsecuentes.
5. **Insuficiencia del Proxy de Aplicación:** `SaedDataSourceProxy` aplica el contexto al momento de invocar `getConnection()`, pero no puede evitar que otra conexión concurrente sobreescriba la SGA mientras la transacción sigue en vuelo.

## 4. Semántica Oficial de Oracle Database y Corrección sobre SGA Purge

Fuentes Oficiales: *Oracle Database SQL Language Reference 19c*, *Oracle Database Security Guide 19c* (Cap. 7), *Oracle Database Concepts 19c* (Cap. 14).

1. **`ACCESSED GLOBALLY` vs `ACCESSED LOCALLY`:**
   * `ACCESSED GLOBALLY`: Atributos almacenados en el Shared Pool de la **SGA**. Requiere `CLIENT_IDENTIFIER` para aislar usuarios.
   * `ACCESSED LOCALLY` (Default): Atributos almacenados en la **UGA/PGA** privada de la sesión. Ninguna otra sesión puede leerlos ni alterarlos.
2. **Corrección sobre el "SGA Purge" con `CLEAR_CONTEXT()`:**
   * La revisión crítica C6.1.2-PRE determinó que **Oracle NO exige ejecutar `CLEAR_CONTEXT()` antes de `CREATE OR REPLACE CONTEXT`**.
   * `DBMS_SESSION.CLEAR_ALL_CONTEXT` opera sobre la sesión invocante. No es un comando administrativo que purgue la SGA completa.
   * En lugar de ejecutar llamadas PL/SQL innecesarias en ATP antes del cambio, la estrategia limpia, estándar y no destructiva recomendada por Oracle DBA es:
     > **Ejecutar el DDL atómico `CREATE OR REPLACE CONTEXT` y, a continuación, reiniciar el servicio backend en Render para drenar y renovar el 100% de las conexiones de HikariCP.**
   * Al cerrarse las conexiones físicas preexistentes, las nuevas sesiones se conectan con PGAs limpias y toman inmediatamente la semántica `SESSION-LOCAL`.

## 8. Plan de Rollback Operacional Completo

### ¿Cuándo ejecutar Rollback?
* Si el PASO 1 falla y corrompe la asociación del contexto.
* Si tras el PASO 3 el backend no puede conectar a la base de datos.
* Si durante el PASO 4 o PASO 5 se detecta fallo en RLS o caída del servicio.

### Procedimiento de Rollback:
1. **Conectado como `ADMIN` en ATP, ejecutar:**
   ```sql
   CREATE OR REPLACE CONTEXT SAED_CTX 
   USING SAED_APP.PKG_SAED_SESSION ACCESSED GLOBALLY;
   ```
2. **Verificar restauración en diccionario:**
   ```sql
   SELECT namespace, schema, package, type 
   FROM dba_context 
   WHERE namespace = 'SAED_CTX';
   -- Debe mostrar TYPE = ACCESSED GLOBALLY
   ```
3. **Reiniciar servicio backend en Render.**
4. **Verificar operatividad en logs y `/actuator/health`.**
