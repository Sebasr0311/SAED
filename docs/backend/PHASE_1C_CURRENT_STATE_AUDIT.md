# PHASE 1C CURRENT STATE AUDIT

## 1. FUENTE DE VERDAD APLICABLE
La fuente de verdad oficial es la base de datos **Oracle SAED V3.9** reconstruida (instancia SAED_V39_FINAL_TEST), complementada por las vistas y RLS establecidas en dicho script, junto con V4.0 y V4.1.

## 2. ESQUEMA DE ORGANIZACIONES
- **Tabla:** ORGANIZACIONES
- **PK:** ID_ORGANIZACION (Identity)
- **UK:** UQ_ORGANIZACIONES_NIT (IDENTIFICACION_FISCAL)
- **Restricciones Not Null:** NOMBRE, IDENTIFICACION_FISCAL, EMAIL_CONTACTO, PAIS, ESTADO, FECHA_CREACION.
- **Restricciones Check:** CK_ORGANIZACIONES_ESTADO (ACTIVA, SUSPENDIDA, INACTIVA).
- **FK:** CREADO_POR -> USUARIOS
- **RLS:** FN_FILTRO_ORGANIZACION (Visible si SUPERADMIN o si coincide ID_ORGANIZACION).

## 3. ESQUEMA DE PROPIEDADES
- **Tabla:** PROPIEDADES
- **PK:** ID_PROPIEDAD (Identity)
- **Restricciones Not Null:** ID_ORGANIZACION, ID_TIPO_PROPIEDAD, NOMBRE, DIRECCION, CIUDAD, PAIS, TIPO_OCUPACION_PREDOMINANTE, ESTADO.
- **Restricciones Check:** CK_PROPIEDADES_ESTADO (ACTIVA, SUSPENDIDA, INACTIVA), CK_PROPIEDADES_OCUPACION.
- **FK:** ID_ORGANIZACION -> ORGANIZACIONES, ID_TIPO_PROPIEDAD -> TIPOS_PROPIEDAD.
- **RLS:** FN_FILTRO_PROPIEDAD (Visible si pertenece a ID_ORGANIZACION de la sesión actual, o si coincide con ID_PROPIEDAD de la sesión actual).

## 4. ESQUEMA DE UNIDADES
- **Tabla:** UNIDADES
- **PK:** ID_UNIDAD (Identity)
- **Restricciones Check:** CK_UNIDADES_AREA, CK_UNIDADES_ESTADO (ACTIVA, INACTIVA, EN_CONSTRUCCION), CK_UNIDADES_CARACT_JSON, CK_UNIDADES_COEFICIENTE.
- **FK:** ID_PROPIEDAD -> PROPIEDADES, ID_BLOQUE -> BLOQUES, ID_TIPO_UNIDAD -> TIPOS_UNIDAD.
- **RLS:** FN_FILTRO_UNIDAD.

## 5. ESQUEMA DE ASIGNACIONES (CRÍTICO)
- **Tabla:** USUARIO_ASIGNACIONES
- **PK:** ID_ASIGNACION
- **Unique Index:** UIX_ASIGNACION_UNICA sobre (ID_USUARIO, ID_ROL, NVL(ID_ORGANIZACION,-1), NVL(ID_PROPIEDAD,-1), NVL(ID_UNIDAD,-1)).
- **Check Constraints:** CK_ASIGNACION_FECHAS (fecha_fin >= fecha_inicio), CK_ASIGNACION_ESTADO (ACTIVA, INACTIVA, VENCIDA, REVOCADA).
- **FK:** ID_USUARIO, ID_ROL, ID_ORGANIZACION, ID_PROPIEDAD, ID_UNIDAD, ASIGNADO_POR.
- **RLS:** FN_FILTRO_ASIGNACION (Aislado por ID_ORGANIZACION o por ID_USUARIO si es residente).

## 6. ESQUEMA DE ROLES
- **Tabla:** ROLES
- **Restricciones Check:** CK_ROLES_ALCANCE (GLOBAL, ORGANIZACION, PROPIEDADES_SELECCIONADAS, PROPIEDAD, UNIDAD), CK_ROLES_ESTADO (ACTIVO, INACTIVO).
- **UK:** UQ_ROLES_CODIGO.

## 7. DISCREPANCIAS Y HALLAZGOS
- PROPIEDADES_SELECCIONADAS es un alcance de rol válido en V3.9, lo que requiere usar la tabla USUARIO_PROPIEDADES_ASIGNADAS asociada a un ID_ASIGNACION.
- No hay disparidad funcional con V3.9: el modelo es puramente transaccional. Spring sólo orquestará el CRUD invocando los queries, y Oracle RLS forzará la seguridad.
