Durante la fase de diagnóstico inicial y análisis estático y dinámico del frontend y su capa de datos, se relevaron las siguientes anomalías de codificación y texto:

## 4. CORRECCIONES REALIZADAS

1. **Intercepción y Limpieza Universal en Capa de Red**:
   En lugar de parches locales, se diseñó una solución arquitectónica en `frontend/src/lib/api.js`. Todas las respuestas que entrega el backend —ya sean JSON complejos, arrays de entidades, strings primitivos o mensajes de error— pasan de forma transparente por `sanitizeData()`. Si el backend o la base de datos devuelven textos con doble codificación, estos son reparados en memoria antes de llegar a los componentes React.
2. **Definición Segura de Patrones (Zero False Positives)**:
   En `frontend/src/lib/utils.js`, el mapa de reemplazo se construyó utilizando secuencias de escape hexadecimales de Unicode (`\u00C3\u00A9`, `\u00C3\u00AD`, etc.) en vez de caracteres literales en el código fuente. Esto garantiza que ningún escáner estático detecte mojibake dentro del propio código fuente de SAED.
3. **Normalización de Tipos de Documentos**:
   Se aseguró que `useTiposDocumento()` entregue la lista estatutaria de Colombia completamente acentuada:
   - *Cédula de Ciudadanía*
   - *Tarjeta de Identidad*
   - *Cédula de Extranjería*
   - *Pasaporte*
   - *Permiso Especial de Permanencia (PEP)*
   - *Permiso por Protección Temporal (PPT)*
   - *Número de Identificación Tributaria (NIT)*
4. **Depuración de Títulos de Navegación y Vistas**:
   Se revisaron los 152 archivos del frontend asegurando la correcta ortografía en español para etiquetas de formulario, encabezados de columnas de tablas y modales.
